# Требования к проекту Call Audio Pipeline

## Функциональные требования

### 1. Приём аудио
- Поддержка WebSocket для потоковой передачи аудио
- Формат аудио:
  - Минимальный: PCM 16-bit, 16000 Hz, mono
  - Расширенный: stereo, RTP, WebRTC, SIP
- Валидация формата при приёме
- Нормализация аудио к стандартному формату

### 2. Обработка аудио
- Voice Activity Detection (VAD) для определения речи
- Нарезка аудио на чанки (250 мс по умолчанию)
- Определение начала и конца речевых сегментов
- Поддержка параметра VAD_THRESHOLD

### 3. Распознавание речи (ASR)
- Интеграция с faster-whisper или whisper.cpp
- Поддержка частичных и финальных транскриптов
- Языковая поддержка (минимум русский и английский)
- Конфиденциальность распознавания

### 4. Диаризация спикеров
- Разделение речи по спикерам
- Поддержка стерео (агент/клиент по каналам)
- Fallback режим при недоступности модели
- Маркировка спикеров: speaker_0, speaker_1, agent, customer

### 5. Хранение данных
- Сохранение аудио в MinIO/S3 или локально
- Сохранение метаданных звонка в PostgreSQL
- Сохранение транскриптов и сегментов
- Ссылки на файлы в хранилище

### 6. API
- REST API для управления звонками
- WebSocket для потоковой передачи аудио
- WebSocket для получения транскриптов в реальном времени
- Health check endpoints

### 7. Мониторинг
- Метрики Prometheus или JSON endpoint
- Логирование с session_id и request_id
- Health check зависимостей (БД, Redis, хранилище)

## Нефункциональные требования

### 1. Производительность
- Задержка обработки < 2 секунд для частичных транскриптов
- Поддержка минимум 5 одновременных потоков на локальной машине
- Эффективное использование ресурсов CPU/GPU

### 2. Надёжность
- Обработка ошибок без падения системы
- Повторные попытки при временных сбоях
- Graceful degradation при недоступности компонентов

### 3. Масштабируемость
- Горизонтальное масштабирование workers
- Разделение компонентов на независимые сервисы
- Брокер сообщений для асинхронной обработки

### 4. Безопасность
- API ключи для доступа к эндпоинтам
- HTTPS в production
- Валидация входных данных
- Защита от перегрузки

## Технические требования

### Стек технологий
- Backend: Python 3.11+
- API: FastAPI
- WebSocket: FastAPI WebSockets
- Брокер: Redis Streams
- База данных: PostgreSQL 16
- Хранилище: MinIO (S3-compatible)
- ASR: faster-whisper
- VAD: silero-vad или webrtcvad
- Диаризация: pyannote.audio или fallback
- Тесты: pytest
- CI: GitHub Actions
- Контейнеры: Docker + docker-compose

### Требования к развёртыванию
- Локальное развёртывание через docker-compose
- Поддержка production окружения
- Переменные окружения для конфигурации
- Non-root пользователь в контейнере

## Критерии приёмки

1. Проект запускается одной командой `docker-compose up -d`
2. Тестовый звонок создаётся командой `make simulate-call`
3. Транскрипт доступен через API
4. Все тесты проходят в CI
5. Документация позволяет новому разработчику начать работу
