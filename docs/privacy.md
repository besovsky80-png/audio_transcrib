# Политика приватности и обработки данных

## Общие принципы

Система Call Audio Pipeline предназначена для обработки аудиозаписей звонков. Мы придаём критическое значение защите персональных данных и приватности участников звонков.

## ⚠️ Критически важные ограничения

### 1. Запрет на обработку без согласия

**Запрещено** загружать в систему реальные персональные данные без явного согласия всех участников звонка.

- Система требует флаг `consent_given: true` для начала обработки
- При `consent_given: false` звонок отклоняется с ошибкой `consent_required`
- Информация о согласии сохраняется в базе данных с временной меткой

### 2. Использование тестовых данных

Для разработки, тестирования и демонстрации используются:

- Синтетические аудиофайлы (сгенерированные программно)
- Тестовые записи с явным согласием участников
- Публичные датасеты с открытой лицензией

**Запрещено** использовать для тестов:
- Реальные звонки клиентов без оформления согласия
- Персональные данные (телефоны, email, номера карт)
- Конфиденциальную коммерческую информацию

## Технические меры защиты

### 1. Согласие на обработку

Перед началом обработки API требует:

```json
{
  "event": "start_call",
  "consent_given": true,
  "source_type": "test_client",
  ...
}
```

При отсутствии согласия:
```json
{
  "error": "consent_required",
  "message": "Обработка аудио требует явного согласия участников"
}
```

### 2. Хранение согласия

В базе данных сохраняются:
- `consent_given: bool` - факт согласия
- `consent_timestamp: datetime` - время получения согласия
- `consent_method: string` - способ получения согласия

### 3. Политика хранения

Автоматическое удаление данных через N дней (настраивается):

```bash
RETENTION_DAYS=30
```

Команда очистки:
```bash
make cleanup
```

### 4. Удаление по запросу

API поддерживает полное удаление звонка:

```bash
DELETE /calls/{session_id}
```

Удаляются:
- Запись в базе данных
- Аудиофайл в хранилище
- Транскрипт и сегменты
- Метаданные

### 5. Маскирование PII

Постобработка текста включает маскирование:

- Телефоны → `[PHONE]`
- Email → `[EMAIL]`
- Номера карт → `[CARD]`
- Паспортные данные → `[PASSPORT]`

## Разрешённые источники аудио

### Для разработки и тестов

✅ Синтетические аудиофайлы
✅ Тестовые записи команды
✅ Публичные датасеты (Common Voice и др.)
✅ Записи с явным письменным согласием

### Для production

✅ Звонки с оформленным согласием клиентов
✅ Внутренние тренировочные звонки сотрудников
✅ Демо-звонки с информированными участниками

❌ **Запрещено:**
- Звонки без документально подтверждённого согласия
- Перехваченные звонки без уведомления участников
- Звонки из источников с сомнительной легитимностью

## Форматы данных

### Минимальный формат

- PCM 16-bit
- 16000 Hz
- mono

### Расширенные форматы

- stereo (для разделения агент/клиент)
- RTP (через адаптер телефонии)
- WebRTC (браузерный источник)
- SIP/SIPREC (интеграция с IP-телефонией)

## Соответствие регуляторным требованиям

### GDPR (ЕС)

- Право на доступ к данным
- Право на исправление
- Право на удаление (право на забвение)
- Право на ограничение обработки
- Информирование о целях обработки

### 152-ФЗ (Россия)

- Согласие на обработку персональных данных
- Локализация баз данных на территории РФ
- Уведомление Роскомнадзора
- Меры защиты информации

### HIPAA (США, медицина)

- Требует дополнительной настройки
- Шифрование данных в покое и при передаче
- Audit logging всех операций
- BAA соглашение с провайдерами

## Рекомендации по развёртыванию

### Development

- Использовать только тестовые данные
- Отключить внешние интеграции
- Локальное хранилище

### Production

- Включить HTTPS/TLS
- Настроить логирование доступа
- Регулярная очистка старых данных
- Мониторинг попыток несанкционированного доступа
- Резервное копирование с шифрованием

## Контакты и инциденты

При обнаружении утечки данных или несанкционированной обработки:

1. Немедленно остановить обработку
2. Задокументировать инцидент
3. Уведомить ответственных лиц
4. Принять меры по устранению
